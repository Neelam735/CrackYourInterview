<Problem difficulty="Medium" link="https://leetcode.com/problems/unique-paths/">

A robot starts in the top-left corner of an `m × n` grid and can only move **right** or **down**. How many different paths reach the bottom-right corner?

**Example:** `m = 3`, `n = 7` returns `28`. `m = 3`, `n = 2` returns `3`.

</Problem>

## Approach

**State.** `dp[r][c]` = the number of paths from the start to cell `(r, c)`.

**Last decision.** The robot's last move into `(r, c)` came either from **above** or from the **left**, and those paths never overlap:

```text nocheck
dp[r][c] = dp[r - 1][c] + dp[r][c - 1]
```

**Base cases.** Every cell in the top row or the left column has exactly one path (keep moving right, or keep moving down).

**Space.** Each row only needs the row above it. Keep one row and update it in place: before the update, `row[c]` still holds the value from the row above, and `row[c - 1]` already holds the new value to the left. So `row[c] += row[c - 1]` does the whole recurrence.

## Solution

<CodeTabs>

```python
def unique_paths(m: int, n: int) -> int:
    row = [1] * n                     # the top row: one path to each cell
    for _ in range(1, m):
        for c in range(1, n):
            row[c] += row[c - 1]      # from above (old row[c]) + from the left
    return row[-1]
```

```java
public int uniquePaths(int m, int n) {
    int[] row = new int[n];
    Arrays.fill(row, 1);  // the top row: one path to each cell
    for (int r = 1; r < m; r++)
        for (int c = 1; c < n; c++) row[c] += row[c - 1];  // from above + from the left
    return row[n - 1];
}
```

<Complexity time="O(m × n)" space="O(n)" />

<Callout type="tip" title="The math shortcut">
Every path is a sequence of `m - 1` down moves and `n - 1` right moves in some order, so the answer is the binomial coefficient `C(m + n - 2, m - 1)`. It's worth mentioning, but the DP generalizes to grids with obstacles ([Unique Paths II](https://leetcode.com/problems/unique-paths-ii/)) and the formula doesn't.
</Callout>
