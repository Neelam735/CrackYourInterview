## The idea

A stack is last-in, first-out: you only ever look at, add to, or remove from the **top**. In Python, a plain `list` works, with `append` to push and `pop` to remove the top, both `O(1)`.

Stacks appear in interviews in two main ways:

1. **Matching and nesting.** The most recent unmatched item is the one that must be closed next: parentheses, HTML tags, undo history, function calls.
2. **Monotonic stack.** Keep the stack sorted (always increasing or always decreasing) to answer "what's the next greater/smaller element?" for every position in one pass.

## When to use it

- Brackets, nesting, or anything that must be closed in reverse order of opening.
- "Next greater element", "previous smaller element", "how many days until...".
- Evaluating expressions, or simulating a process where the latest item is processed first.

## Problem 1: Valid Parentheses

<Problem difficulty="Easy" link="https://leetcode.com/problems/valid-parentheses/">

Given a string containing only the characters `()[]{}`, decide whether it's valid: every opener is closed by the same type of bracket, in the correct order.

**Example:** `"{[()]()}"` is valid, `"([)]"` is not.

</Problem>

Push every opener. When you see a closer, it must match the opener on top of the stack, since that's the most recent one still open. At the end, the stack must be empty.

<Visualizer id="valid-parentheses" />

```python
def is_valid(s: str) -> bool:
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for char in s:
        if char in pairs:
            if not stack or stack[-1] != pairs[char]:
                return False
            stack.pop()
        else:
            stack.append(char)
    return not stack
```

<Complexity time="O(n)" space="O(n)" />

## Problem 2: Daily Temperatures

<Problem difficulty="Medium" link="https://leetcode.com/problems/daily-temperatures/">

Given daily `temperatures`, return an array `answer` where `answer[i]` is the number of days you have to wait after day `i` to get a warmer temperature, or `0` if there's no such day.

**Example:** `[73, 74, 75, 71, 69, 72, 76, 73]` returns `[1, 1, 4, 2, 1, 1, 0, 0]`.

</Problem>

### Brute force

For each day, scan forward until you find a warmer day: `O(n²)`.

### Monotonic stack

Keep a stack of days that are **still waiting** for a warmer day. Their temperatures are always decreasing from bottom to top, because a warmer day would have resolved any colder day below it.

When a new day arrives, pop every waiting day that's colder than it. Today is their answer. Then push today.

<Visualizer id="daily-temperatures" />

```python
def daily_temperatures(temperatures: list[int]) -> list[int]:
    answer = [0] * len(temperatures)
    stack = []  # indices of days still waiting, temps decreasing
    for i, temp in enumerate(temperatures):
        while stack and temperatures[stack[-1]] < temp:
            j = stack.pop()
            answer[j] = i - j
        stack.append(i)
    return answer
```

<Complexity time="O(n)" space="O(n)" />

<Callout type="info" title="Why it's O(n)">
Each index is pushed once and popped at most once, so the inner `while` loop runs at most `n` times in total across the whole algorithm.
</Callout>

<Callout type="tip">
Store **indices** on the stack, not values. You can always look up the value with `temperatures[i]`, but you can't recover the index from a value, and many problems need the distance between positions.
</Callout>
