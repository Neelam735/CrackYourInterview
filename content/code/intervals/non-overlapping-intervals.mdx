<Problem difficulty="Medium" link="https://leetcode.com/problems/non-overlapping-intervals/">

Given an array of `intervals`, return the minimum number of intervals you need to remove so that the rest don't overlap. Intervals that only touch, like `[1, 2]` and `[2, 3]`, don't overlap.

**Example:** `[[1, 2], [2, 3], [3, 4], [1, 3]]` returns `1` (remove `[1, 3]`).

</Problem>

## Reframe

Removing as few intervals as possible is the same as **keeping as many as possible**. This is the classic activity selection problem.

## Greedy: earliest end first

Sort by **end** time and always keep the interval that finishes first.

Why is that safe? Of all the intervals you could pick next, the one that ends earliest leaves the **most room** for everything after it. Any solution that picks a different interval could swap it for the earliest-ending one without creating a new overlap. So picking the earliest end never makes things worse.

Walk through the sorted list remembering `prev_end`, the end of the last interval you kept:

- If the interval starts at or after `prev_end`, keep it and update `prev_end`.
- Otherwise it overlaps the one you kept, so remove it (count it).

## Solution

<CodeTabs>

```python
def erase_overlap_intervals(intervals: list[list[int]]) -> int:
    intervals.sort(key=lambda x: x[1])   # earliest end first
    removed = 0
    prev_end = float("-inf")
    for start, end in intervals:
        if start >= prev_end:
            prev_end = end               # keep it
        else:
            removed += 1                 # overlaps the last kept interval
    return removed
```

```java
public int eraseOverlapIntervals(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[1], b[1]));  // earliest end first
    int removed = 0;
    long prevEnd = Long.MIN_VALUE;
    for (int[] cur : intervals) {
        if (cur[0] >= prevEnd) prevEnd = cur[1];  // keep it
        else removed++;                           // overlaps the last kept interval
    }
    return removed;
}
```

function eraseOverlapIntervals(intervals) {
  intervals.sort((a, b) => a[1] - b[1]); // earliest end first
  let removed = 0;
  let prevEnd = -Infinity;
  for (const [start, end] of intervals) {

  }
  return removed;

<Complexity time="O(n log n)" space="O(1) besides sorting" />

<Callout type="warning">
Sorting by **start** time doesn't work here. With `[[1, 10], [2, 3], [4, 5]]`, keeping `[1, 10]` first forces you to remove two intervals, while keeping the two short ones removes only one.
</Callout>
