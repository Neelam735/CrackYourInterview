## The idea

If the input is sorted, checking the middle element tells you which **half** can't contain the answer. Throw that half away and repeat. Each step halves the remaining range, so a million elements take about 20 steps: `O(log n)`.

Binary search goes beyond sorted arrays. It works whenever you can ask a yes/no question that is **monotonic**: false, false, ..., false, true, true, ..., true. Binary search finds where the answer flips.

## When to use it

- The input is **sorted** (or rotated sorted).
- The problem asks for `O(log n)` time.
- You need the **minimum or maximum value that satisfies a condition**, and if a value works, every larger (or smaller) value works too. This is called "binary search on the answer".

## Problem 1: Binary Search

<Problem difficulty="Easy" link="https://leetcode.com/problems/binary-search/">

Given a sorted array of distinct integers `nums` and a `target`, return the index of `target`, or `-1` if it isn't there.

**Example:** `nums = [1, 3, 5, 7, 9, 11, 13, 15, 17]`, `target = 15` returns `7`.

</Problem>

Keep the range `[lo, hi]` where the target could still be. Compare against the middle element and discard the half that can't contain it.

<Visualizer id="binary-search" />

```python
def search(nums: list[int], target: int) -> int:
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            lo = mid + 1   # target is to the right
        else:
            hi = mid - 1   # target is to the left
    return -1
```

<Complexity time="O(log n)" space="O(1)" />

<Callout type="warning" title="Off-by-one bugs">
Most binary search bugs come from mixing conventions. Pick one and stick to it: here `[lo, hi]` is **inclusive**, so the loop runs `while lo <= hi` and you move to `mid + 1` or `mid - 1`, always excluding `mid` once it's been checked.
</Callout>

## Problem 2: Search in Rotated Sorted Array

<Problem difficulty="Medium" link="https://leetcode.com/problems/search-in-rotated-sorted-array/">

A sorted array of distinct integers was rotated at an unknown pivot, for example `[0, 1, 2, 4, 5, 6, 7]` became `[4, 5, 6, 7, 0, 1, 2]`. Given `target`, return its index or `-1`, in `O(log n)` time.

</Problem>

### Approach

Split the array at `mid`. Even after rotation, **at least one half is still sorted**. Check which one it is by comparing `nums[lo]` with `nums[mid]`. If the target falls within the sorted half's range, search there; otherwise search the other half.

```python
def search_rotated(nums: list[int], target: int) -> int:
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[lo] <= nums[mid]:                  # left half is sorted
            if nums[lo] <= target < nums[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:                                      # right half is sorted
            if nums[mid] < target <= nums[hi]:
                lo = mid + 1
            else:
                hi = mid - 1
    return -1
```

<Complexity time="O(log n)" space="O(1)" />

## Problem 3: Koko Eating Bananas

<Problem difficulty="Medium" link="https://leetcode.com/problems/koko-eating-bananas/">

There are `piles` of bananas and Koko has `h` hours. Each hour she picks one pile and eats up to `k` bananas from it. Find the **minimum** eating speed `k` that lets her finish within `h` hours.

**Example:** `piles = [3, 6, 7, 11]`, `h = 8` returns `4`.

</Problem>

### Binary search on the answer

Nothing here is sorted, but the question "can she finish at speed `k`?" is monotonic: if speed `k` works, any faster speed works too. So binary search over possible speeds, from `1` to `max(piles)`, for the first speed that works.

```python
import math

def min_eating_speed(piles: list[int], h: int) -> int:
    def can_finish(k: int) -> bool:
        return sum(math.ceil(p / k) for p in piles) <= h

    lo, hi = 1, max(piles)
    while lo < hi:
        mid = (lo + hi) // 2
        if can_finish(mid):
            hi = mid        # mid works; maybe something smaller does too
        else:
            lo = mid + 1    # mid is too slow
    return lo
```

<Complexity time="O(n log m), m = max(piles)" space="O(1)" />

<Callout type="interview">
This "find the first value where a condition becomes true" template (`while lo < hi`, `hi = mid` or `lo = mid + 1`) solves a whole family of medium and hard problems. If a problem asks for a minimum or maximum and brute-forcing every candidate value is too slow, ask yourself whether the check is monotonic.
</Callout>
