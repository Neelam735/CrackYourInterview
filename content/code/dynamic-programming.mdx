## The idea

Dynamic programming (DP) is for problems where the same smaller subproblems come up again and again. Instead of recomputing them, you **solve each subproblem once and store the answer**.

A problem is a good fit for DP when it has two properties:

- **Optimal substructure:** the answer can be built from answers to smaller versions of the same problem.
- **Overlapping subproblems:** a plain recursive solution would solve the same smaller problem many times.

### A recipe for any DP problem

1. **Define the state.** In words: "`dp[i]` is the best answer for the first `i` items."
2. **Find the recurrence.** How does `dp[i]` follow from smaller states? Think about the **last decision**.
3. **Set the base cases.** The smallest inputs you can answer directly.
4. **Choose the order.** Fill the table so every state's dependencies are already computed.
5. **Read off the answer**, often `dp[n]` or the last cell.

You can write it **top-down** (recursion plus a cache, called memoization) or **bottom-up** (a loop that fills a table). They do the same work; bottom-up avoids recursion limits and often lets you shrink the table.

## When to use it

- The problem asks for a **count** ("how many ways"), a **minimum/maximum**, or **is it possible**.
- Each step involves a **choice** (take or skip, go left or right) and a greedy choice doesn't always work.
- Brute force would try every combination of choices: exponential time.

## Problem 1: Climbing Stairs

<Problem difficulty="Easy" link="https://leetcode.com/problems/climbing-stairs/">

You're climbing a staircase with `n` steps. Each time you can climb 1 or 2 steps. How many distinct ways can you reach the top?

**Example:** `n = 3` returns `3`: 1+1+1, 1+2 and 2+1.

</Problem>

Think about the **last move**. To stand on step `i`, you came from step `i - 1` (with a 1-step) or from step `i - 2` (with a 2-step). So `ways(i) = ways(i - 1) + ways(i - 2)`, the Fibonacci recurrence.

The plain recursion recomputes the same steps exponentially many times. Each state only needs the previous two, so two variables are enough.

<CodeTabs>

```python
def climb_stairs(n: int) -> int:
    prev, curr = 1, 1  # ways to reach step 0 and step 1
    for _ in range(2, n + 1):
        prev, curr = curr, prev + curr
    return curr
```

```java
public int climbStairs(int n) {
    int prev = 1, curr = 1;  // ways to reach step 0 and step 1
    for (int i = 2; i <= n; i++) {
        int next = prev + curr;
        prev = curr;
        curr = next;
    }
    return curr;
}
```

```cpp
int climbStairs(int n) {
    int prev = 1, curr = 1;  // ways to reach step 0 and step 1
    for (int i = 2; i <= n; i++) {
        int next = prev + curr;
        prev = curr;
        curr = next;
    }
    return curr;
}
```

```javascript
function climbStairs(n) {
  let prev = 1; // ways to reach step 0
  let curr = 1; // ways to reach step 1
  for (let i = 2; i <= n; i++) {
    [prev, curr] = [curr, prev + curr];
  }
  return curr;
}
```

</CodeTabs>

<Complexity time="O(n)" space="O(1)" />

## Problem 2: House Robber

<Problem difficulty="Medium" link="https://leetcode.com/problems/house-robber/">

Houses along a street hold `nums[i]` money each. You can't rob two adjacent houses. Return the most money you can rob.

**Example:** `nums = [2, 7, 9, 3, 1]` returns `12` (houses 0, 2 and 4: 2 + 9 + 1).

</Problem>

Greedy fails here: always grabbing the richest house can block two good neighbours. Follow the recipe instead.

- **State:** `dp[i]` = the most money from houses `0..i`.
- **Last decision:** at house `i`, either **skip** it (keep `dp[i - 1]`) or **rob** it (`dp[i - 2] + nums[i]`, since house `i - 1` must be skipped).
- **Recurrence:** `dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])`.

<Visualizer id="house-robber" />

<CodeTabs>

```python
def rob(nums: list[int]) -> int:
    prev, curr = 0, 0  # dp[i - 2], dp[i - 1]
    for money in nums:
        prev, curr = curr, max(curr, prev + money)
    return curr
```

```java
public int rob(int[] nums) {
    int prev = 0, curr = 0;  // dp[i - 2], dp[i - 1]
    for (int money : nums) {
        int next = Math.max(curr, prev + money);
        prev = curr;
        curr = next;
    }
    return curr;
}
```

```cpp
int rob(const vector<int>& nums) {
    int prev = 0, curr = 0;  // dp[i - 2], dp[i - 1]
    for (int money : nums) {
        int next = max(curr, prev + money);
        prev = curr;
        curr = next;
    }
    return curr;
}
```

```javascript
function rob(nums) {
  let prev = 0; // dp[i - 2]
  let curr = 0; // dp[i - 1]
  for (const money of nums) {
    [prev, curr] = [curr, Math.max(curr, prev + money)];
  }
  return curr;
}
```

</CodeTabs>

<Complexity time="O(n)" space="O(1)" />

<Callout type="tip" title="Shrinking the table">
The visualization shows the full `dp` array to make the recurrence visible, but each entry only depends on the two before it. Keeping just those two values cuts space from `O(n)` to `O(1)`. Mention this optimization after you have the table version working.
</Callout>

## Problem 3: Longest Common Subsequence

<Problem difficulty="Medium" link="https://leetcode.com/problems/longest-common-subsequence/">

Given two strings `text1` and `text2`, return the length of their longest common subsequence. A subsequence keeps the characters' order but can skip characters.

**Example:** `text1 = "abcde"`, `text2 = "ace"` returns `3` (`"ace"`).

</Problem>

With two inputs, the state needs two indices.

- **State:** `dp[i][j]` = the LCS length of the first `i` characters of `text1` and the first `j` characters of `text2`.
- **Last decision:** compare the last characters, `text1[i - 1]` and `text2[j - 1]`.
  - **Equal:** they can both be part of the LCS, so `dp[i][j] = dp[i - 1][j - 1] + 1`.
  - **Different:** at least one of them isn't used, so drop one: `dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])`.
- **Base case:** an empty string has LCS 0 with anything, so row 0 and column 0 are 0.

<Visualizer id="longest-common-subsequence" />

<CodeTabs>

```python
def longest_common_subsequence(text1: str, text2: str) -> int:
    m, n = len(text1), len(text2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i - 1] == text2[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[m][n]
```

```java
public int longestCommonSubsequence(String text1, String text2) {
    int m = text1.length(), n = text2.length();
    int[][] dp = new int[m + 1][n + 1];
    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (text1.charAt(i - 1) == text2.charAt(j - 1)) {
                dp[i][j] = dp[i - 1][j - 1] + 1;
            } else {
                dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
            }
        }
    }
    return dp[m][n];
}
```

```cpp
int longestCommonSubsequence(const string& text1, const string& text2) {

            }
        }
    }
    return dp[m][n];
}
```

```javascript
function longestCommonSubsequence(text1, text2) {
  const m = text1.length;
  const n = text2.length;
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));
  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (text1[i - 1] === text2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1] + 1;
      } else {
        dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
      }
    }
  }
  return dp[m][n];
}
```

</CodeTabs>

<Complexity time="O(m × n)" space="O(m × n)" />

<Callout type="interview">
Say the state definition out loud before writing any code: "`dp[i][j]` means the LCS of the first `i` letters and the first `j` letters." Interviewers grade DP on whether your state and recurrence are right. Once those are clear, the code is just two loops.
</Callout>
